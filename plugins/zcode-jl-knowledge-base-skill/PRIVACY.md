# 隐私说明

最后更新：2026-09-03

JL Knowledge Base Skill 是一个面向 Codex、Gemini CLI 和 ZCode 的杰理（JL）知识与工程扩展。本文说明在知识查询和知识贡献时处理哪些数据、不处理哪些数据，以及用户如何关闭贡献。

> **服务状态：**公开测试服务已经开启；测试期服务地址和可用性可能调整。

## 1. 一次明确授权

- 下载、安装或启用插件本身不自动等于同意，也不会替用户取得知识访问资格。完全离线的旧包不能收到联网升级提示；v0.7.1 收到提示后仍需从 GitHub `https://github.com/dongke141219/jl-knowledge-base-skill` 或 Gitee `https://gitee.com/fofo123/jl-knowledge-base-skill` 手动升级到 v0.8.0。
- 首次访问共享知识库前，客户端必须醒目展示“知识共同成长计划”和上传边界，并要求用户本人在对话输入框中准确输入“同意”。不得根据安装动作、历史消息、默认设置或模型自行判断代替用户同意。
- 授权生效后，已确认属于 JL 的任务可进行一次范围化查询；只有任务完成后确实形成新的、可复用、本地证据支持的工程结论，才提交至多一条小型、结构化、脱敏的待验证候选，不再每次重复询问。
- 普通问答、浏览、排版、重复结论、查询返回片段的转述，以及查询未命中后仍没有可靠结论的任务都不自动上传。共享服务未命中或不可用时，AI 继续正常完成本地工作，不得循环重试或编造解决方案。
- 知识查询采用匿名公共访问，不要求注册、登录、申请、逐人批准或个人凭据，但必须先完成上述一次明确同意。未同意时，服务器拒绝创建知识任务和返回共享知识片段。

## 2. 可自动上传的字段

客户端只允许上传已通过本地校验的结构化候选，字段限于：

- 功能与语义标识：稳定通用的 `product_id`、`domain_id`、`capability_id`、`semantic_id`、`node_type`、`parent_semantic_id`；不得用客户、公司、项目、账号或路径命名分类。
- 候选类别：可复用解决经验 `solution`，或尚无可靠答案的知识缺口 `knowledge_gap`。
- 简短知识内容：`title`、`summary`、`workflow`、`validation`、`limitations`。
- 证据状态：`lifecycle_status`、`evidence_level`。
- 适用范围：通用产品类型、芯片型号、SDK 版本、平台与功能标签。
- 简短关系：关系类型与目标语义标识。
- 去重字段：由规范化候选生成的 SHA-256 幂等标识，不是源码或凭据的哈希。

服务端为了匿名限流、去重、来源撤回和安全审计，还可保留服务端签发的短期任务标识、匿名网络来源的不可逆脱敏分桶、提交时间、来源分类、请求计数和脱敏审计值。服务端不要求或保存 GitHub 用户的客户平台账号，也不向公开用户发放访问凭据。

v0.8.0 起，服务器会比较客户端版本并返回最新版本、最低兼容版本和固定升级动作编号。服务器不能下发命令、路径或脚本正文。客户端升级器只运行包内预置的 Codex/Gemini 白名单命令；ZCode 当前只返回人工升级。升级结果上报仅包含随机尝试标识的不可逆 HMAC、客户端类别、升级前/目标/实际版本、执行阶段、成功/失败、是否触发固定回退和固定错误码；不包含命令、原始输出、路径、设备名、账号、IP 明文或用户身份。失败尝试六小时内不自动重复。

## 3. 绝不自动上传的内容

- 源码、源码片段、完整配置文件或可重建工程的内容。
- 原始日志、完整编译输出、文件包、固件、KEY 文件或 KEY 内容。
- 客户、公司、项目或个人名称，邮箱、电话号码及其他可识别身份信息。
- 本地路径、网络路径、主机名、内网或公网地址、URL。
- 密码、令牌、API 密钥、私钥、会话信息或其他访问凭据。
- 私有协议载荷、授权材料，以及网关返回的私有知识片段原文。

本地校验器是最后一道保守检查，不代表可以先向它提供原始源码或日志再依赖它脱敏。候选必须在进入校验器之前就已经结构化和脱敏。

## 4. 本地数据

客户端可在当前操作系统用户的应用状态目录中保存：

- 一次授权回执和撤销状态。
- 不含身份和项目原文的本地计数。
- 尚未成功提交的脱敏候选 outbox。
- 已被服务端接收的候选规范化 SHA-256 标识的有限回执历史，用于避免同一结论重复上传；它不含候选正文、源码、路径或身份。

outbox 不保存网关地址、访问凭据、服务端 `task_id`、源码、原始日志或网关返回的片段。未发送候选最长在本地保留 30 天，成功接收后从本地队列删除。

v0.8.0 在 Codex、Gemini CLI 和 ZCode 分别使用各客户端支持的生命周期事件。hook 只做有界的本地目录/文件名特征检查来判断当前项目是已确认、待确认或非 JL，并按会话保存工作区哈希、布尔状态、服务端 `task_id` 的 SHA-256、有限候选哈希、升级目标版本、升级是否已提示/尝试/上报，以及结果枚举（`usage_recorded` / `solution_candidate` / `server_gap` / `query_unavailable` / `local_only`）。它不保存原始提示、原始 `task_id`、源码、日志、项目路径、转录、知识片段、原始工具输出或扫描到的文件名。用户仍应在客户端查看并信任已安装的 hook。

## 5. 撤销、撤回与否定

- 用户可随时撤销共同贡献授权。客户端撤销会立即停止未来自动贡献，并删除该用户设备上尚未发送的本地 outbox；撤销后同时失去共享知识库访问资格，但仍可使用自己的 AI 客户端处理本地 SDK。
- **本地撤销不会自动删除已经被中央服务接收的未验证记录。**
- 对已接收内容的撤回或明确否定，由授权支持渠道按“提交来源”处理：停止推荐或移除该来源的 observation，保留必要的撤回/失败审计记录。
- 若同一语义知识节点还有其他独立有效来源，撤回某一来源不会误删其他来源；若被撤回来源是唯一支持，服务端应停止推荐或依运营策略移除该未验证节点。

## 6. 保留期限

本地未发送 outbox 的最长保留期为 30 天。公开测试期间，候选知识、知识缺口、来源观察、撤回/失败记录和必要安全审计仅为知识服务运行、审核、去重、撤回和安全处理而保留。共享知识库在逻辑上只有一个，其中包括能实现的功能、工程实现指南、产品/芯片/SDK 适用范围、边界、问题解决经验以及编译/实机证据。新贡献先进入同一个知识库内的候选区接受安全审核；通过的解决经验才会按完整功能链进入正式区，在此之前不会作为共享答案返回。用户可通过仓库维护渠道提出与自己提交来源相关的撤回请求。

## 7. AI 额度与模型边界

外部用户和公司工程师使用自己的 Codex、Gemini CLI、ZCode，或经作者完成适配的其他客户端账号、模型和额度完成自己的工程任务及候选摘要。本地 outbox 只做 JSON 校验和存储；知识网关只做匿名限流、任务约束、查询、去重和存储。两者本身都不启动模型，不调用知识库所有者的 AI 编程客户端，也不消耗所有者的 AI 额度。

## 8. GitHub 版与内部平台边界

- GitHub 下载版只获得少量、与当前任务相关的知识片段，不能下载、浏览或导出完整知识库。
- GitHub 版不要求注册客户网页账号，也不需要逐个申请或审批知识查询资格。
- 是否同意参加共同成长由使用者自己决定；不同意或撤销后不能访问共享知识库，但不影响使用者用自己的 AI 客户端处理本地 SDK。
